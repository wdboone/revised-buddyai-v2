# Deliverables — illustrative examples

These are simplified, representative versions of the research artifacts referenced in the activity and
sprint logs. They exist so a reviewer can see the shape and substance of the work without needing the
full research workspace.

Every example uses a **fictional persona (Dana Whitfield)** — no real personal data. The real work runs
on actual persona datasets; those are kept out of this repo. The point here is the *design*, not the data.

## What's here

| Folder | Deliverable it illustrates | What it shows |
|---|---|---|
| `user-model-versions/` | Four user-model design versions | Four increasingly structured ways the app could represent a user, same person in each. |
| `automated-evaluation/` | Automated evaluation | The coaching prompt, the evaluation questions, and a sample results summary. |
| `self-interview-instrument/` | Self-interview instrument | The instrument used to collect persona data through structured self-interview. |

## Why this matters for the build

Buddy AI's coaching quality depends on how well it understands the user. These artifacts test *which way of
representing a user* produces the best coaching, so the build can adopt an evidence-backed approach to its
user-modeling feature rather than picking one by intuition.
